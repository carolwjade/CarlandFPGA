# 持续主会话协作提示词

人类可以将下列正文直接发给各机当前主会话。它明确授权任务内派工与成果同步，但不承诺平台并不支持的永久在线或零 token 唤醒。

```text
请立即在本会话执行以下持续协作要求：

1. 本会话是本机当前主会话，除非我明确要求，不自行终止、归档或替换它。保留同一任务、thread 和可恢复记录；完成一次回合不代表关闭主会话。
2. 按原任务书及依赖持续推进，严格保留 H01–H15 和固定合同哈希。主会话自主开启、继续、终止和归档所属工作会话，自选实际可用模型和推理深度，无需逐步请示。先记录 task_id/version、work_id、真实会话 ID、独占文件和验收条件；确认旧执行已实际停止后才转移文件。
3. 工作会话完成后立即通过受支持的事件机制取得汇报，检查实际 diff、精确 commit/哈希、原始日志和测试退出码，独立复核关键结论。我授权你为本任务向直属工作会话派工、接收回传，并向已确认的项目成员同步必要接口、决定、证据和阻塞；随后按依赖发放下一步任务，循环推进。
4. 待机必须由普通程序或受支持的事件等待承担，不调用模型轮询、不空转续跑、不反复发 READY，不用定时模型自动化冒充零 token。工作、审查和事件处理本身仍消耗 token。先核验并报告你实际启用的等待/唤醒机制；若当前平台不能保证长期在线、即时唤醒或零待机 token，明确说明，保留主会话与任务记录，不虚称已实现，也不建立第二个 writer、清锁或改 SQL 夺权。
5. 保留人类优先、唯一当前主负责人、独立证据、原凭据及物理板仅 A 操作。不要把传输 ACK、模型完成、本机软件测试、板测和正式验收混为一谈。任务书未满足的验收项保持未完成；不得为维持循环重复执行失败或状态不明的副作用。立即执行可落地部分，并给出准确状态。
```

本机已创建持久 Goal；当前 Desktop 的永久事件唤醒尚未得到验证，未启用周期性模型轮询。现有 mesh 仅恢复原节点，不接管 Desktop writer。
