# 项目书需求对应

依据工作区项目书 `docs/superpowers/specs/2026-09-29-fpga-multi-agent-design.md` v0.8，以及 `2026-10-10-autonomous-routing-design.md`。这里保存操作要求，不列本轮尚未验证事项，也不将需求描述为测试通过。

| 项目书位置 | 技能执行要求 |
| --- | --- |
| §1–2 三机职责 | 每机独立控制器、自己的 Codex 登录和本地工程。A 统筹依赖与唯一实板；A 不是其他节点工作的唯一入口。 |
| §3 跨网通信 | 各机配置另外两台当前地址；HMAC 验证身份，持久收发、去重与断线补发。B/C 直接互通。 |
| §4 六个身份 | 每机一个 Astra 和一个共用 DeepSeek 身份。子实例按有效委托操作群，扩缩不增机器人。 |
| §5 指令与归属 | 人类最高优先级；定向消息归指定节点。无对象共享新任务须远端认领成功；失联不自动转移所有权。暂停跨重启持久保存。 |
| §5 恢复覆盖 | 重连先核对人类指令、版本和暂停；按既有恢复记录核对历史分页、话题回复、消息修改/撤回。缺口只阻塞受影响工作。 |
| §6 模型与会话 | 按 2026-10-15 人类更新，主会话自由安排所属会话生命周期、实际可用模型及推理深度；沿用本人认证。Desktop/native 不以 mesh 租约为前置，仍记录任务、独占文件和证据；mesh job 保留自身去重和租约。 |
| §7 零模型等待 | 结束有效模型回合；程序等事件、过滤心跳和重复消息。不得用推理轮询维持待命。 |
| §8 额度与上下文 | 读取实际 bucket/window/reset 和时间，空值为未知。额度恢复重新核对身份、暂停、任务与未完成操作；不换他人账号、不撤销人工暂停。长任务保存交接。 |
| §9 共享板卡 | A 独占准备、上传、烧录、执行、采集、清理。结果绑定操作、请求、实际提交与产物哈希；未知副作用先核对原操作。 |
| §10 工程保存 | 各机独立目录/分支；稳定批次保存源码、测试、原始证据及清单。远端不可达保留本地提交，恢复后按规则同步，无静默覆盖。 |
| §11–12 可观察状态 | 区分节点连接、模型工作、等待原因、队列与未同步提交；验收绑定真实任务与证据。阶段结束常驻服务继续监听。 |
| §11 协作收益 | 质量主模型保留决策/验收，子代理按需要执行。只有测量同等任务的质量、端到端耗时及实际套餐 usage 才评价收益，不把调用数等同节省比例。 |

## 已明确的更新覆盖旧条目

- 2026-10-07 起仓库为公开；贡献使用现有 fork/PR。未指定负责人的共享任务认领仍需要协调分支写权限。
- v0.7 起没有默认两个子实例、最低数量或预建待命池；2026-10-15 起模型与深度也由主会话自选，不再强制最高深度。
- 2026-10-13 人类要求静默在场：不主动群发上下线/重连健康新闻，覆盖旧项目书 §3–4 的自动状态公告。程序继续内部检查和恢复，有实际任务阻塞时简洁报告影响。

- 2026-10-13 本轮要求恰好两个项目级技能、多机与单机都分 A 和共用 B/C；清理全局旧技能及可发现备份，统一从项目内加载，新会话生效。
- 2026-10-13 飞书 API 限制用 Tailscale、GitHub 和已授权聊天框直发补齐，不要求解除所有限制。状态与身份仍须真实，不能替代原应用恢复证据。

具体流程见同目录 `protocol.md` 和 `handoff.md`；新任务若明确改变目标，以人类最新任务版本为准。

- 2026-10-15 人类扩大主会话权限：可自主开启、继续、终止和归档多个工作会话，全部实际可用模型和推理深度自选，后续无需逐项权限确认；直接清理旧版冲突限制。H01-H15、实际停止核验、唯一负责人、凭据和证据规则不变。
