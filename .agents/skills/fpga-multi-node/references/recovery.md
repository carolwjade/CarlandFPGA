# 本轮已发生问题与解决方法

只收录已有现场和处理证据的症状。下表是针对相同症状的定位方法，不能从历史成功推断当前状态。不要为了“验证技能”重做停服、断网或板测。

| 实际症状 | 已采用的定位与处理 |
| --- | --- |
| GitHub 网页已开，CLI 推送仍未认证 | 核对既有 gh 实际账号与目标仓库权限；在当前进程引用已有本机 gh profile，完成原账号登录后再推送并读回完整 SHA。不复制他人凭据、不改全局认证。fork/PR 权限与协调分支写权限分别核验。 |
| Tailscale 页面登录后 Windows 节点仍 NoState/未 online | 查看 daemon 的实际状态和当前 profile，选回原团队账号；本轮 C 使用原 profile 的 unattended 设置恢复 Running/self online，随后实测 HMAC。只在该症状和原权限下采用，不把打开网页当联网完成。 |
| 当前地址已改，常驻发送仍命中旧地址/走错误代理 | 同一当前地址对比直连和代理路径、正确/错误 HMAC 响应，再核对运行实例缓存和 config。只为该进程补原 peer/loopback 的 NO_PROXY；空闲栅栏内重载原服务使地址生效，不关闭全局 VPN/改 provider。 |
| 相同 operation_id 因新生成 sent_at 被当不同内容 | 已修复 prepare_outbound_operation：只忽略新生成时间参与重复比较，重用原规范 payload/sent_at；实质字段变化仍拒绝。重复调用核对一条 outbox、原 ACK 和实际执行记录；不以新操作号替代旧操作。 |
| 断线后的原 outbox 需要恢复 | 保留原 envelope、message_id、operation_id 和 ACK；由原常驻发送器补送尚未 ACK 行。HttpPeer 的 flush_lock 仅限单进程，另起临时 sender 会绕过保护，不能用于恢复。 |
| .ps1 被 ExecutionPolicy 拒绝，调用标志误像已经 Stop | 检查 Task XML、旧进程/创建时间与持久结果，确认实际未 Stop；保留失败，不改执行策略或重放旧版本。质量主模型另立工作版本，用既有 stop_idle_node 的正常 Task cmdlet 回调完成必要维护，账本写入栅栏持有至原进程树真实退出。 |
| 错投节点的旧人类消息阻碍 idle 检查 | 由原负责人核对真实目标、原始消息和是否已执行，只审计结束确认未执行的错投行。不要伪造模型完成、清空数据库或把他机任务改为本机所有。 |
| DeepSeek completed，但写入越出 ownership | 独立检查实际 diff/哈希，保留原文件与违规证据，不追认权限、不重放 child。主模型另立明确工作及独占目录接管修正，重新验证后才接收。派工前给精确文件/目录及只读限制。 |
| 停服辅助代码遗漏 Task root、独占 claim、非空 Job 与截止复核 | 修正计划绑定完整 PID/父子/创建时间；首次写入用独占 claim，Stop 意图单独落盘；Job 必须有效且非空；昂贵检查后与 Stop 前复核剩余时间及实时 guard。根主会话在独占目录完成定向本机测试；这些测试只证明辅助代码。 |
| PowerShell 文本转码/换行导致 Git 文件哈希不同 | 通过 Python subprocess 读取 git blob 原始 bytes 后计算哈希；不通过 shell 文本管道生成交接证据。文本包更新按既有 canonical_hash 处理 LF/CRLF，二进制按原字节。 |
| 中文输出 GBK 异常、相对 as_uri、inspect.py 遮蔽标准库 | 当前 Python 进程用 -X utf8，文件 UTF-8；Path.resolve() 后创建 SQLite 只读 URI；采集器采用专用模块名。不要为这些局部问题改全局配置或递归扫描整个运行目录。 |
| 飞书 token API 21001，原应用群同步失败 | 保留原错误、请求 ID、发生时间和 queued 行；本轮人类选择 peer/GitHub/聊天框直发替代。校验目标群和实际发送者，读回真实公告/附件。不要把替代通道成功写成原 token API 已修复，也不要为了绕过建立新机器人或复制凭据。 |
| Git push 443 超时，但公共 PR 源码仍可读 | 保存本地提交与网络错误；本轮 C 经 GitHub REST 读取实际 raw blob 并核对 Git SHA-1/SHA-256，留下同 PR review。只能声称已实际发布的反馈，不能把本地 review 提交当已推送；恢复推送先核对远端落地状态。 |
| Windows 长路径在测试前阻止 Git checkout | 先区分 checkout/harness 与测试失败；在该命令使用 -c core.longpaths=true 的进程范围配置，核对完整文件，再执行原验证，不改全局配置。 |
| 验收沟通与临时框架过度展开 | 最新人类明确基础范围后复用可信实测，结束无关严格专项；只补影响本轮完成条件的证据。派工一次后退出有效模型回合，程序等待回执，不重复制造 READY/询问任务挡住 idle。 |

## 必要维护的共同闭环

先保存现有错误、配置差异、原收发/任务记录及实际进程证据。质量主模型定位原因并明确新的修复工作/归属；只改必要部分。沿用已有 Update/stop_idle_node 的空闲栅栏与唯一服务任务，不停止活动工作，不绕过未知执行状态。

维护后核对原服务实际新 PID、原身份/连接、当前地址与原持久结果，保存恢复证据。扫码、云授权、共享密钥缺失和平台权限准确合并报告，继续独立工作。自动更新不覆盖未识别的本地补丁；先比较源码与 MANIFEST，再有依据地合并。

## 经验出处

项目基准与后续覆盖条目见 [需求对应](requirements.md)。2026-10-11 原地更新/幂等、2026-10-13 基础协作验收、普通新会话接入与技能安装审查，以及 BOARD-20261013-A metadata/BRAM 回证是本页的现场来源。纯进度查询修复与收件审计要求取得被问节点的持久状态，不用本机 health 或群 ACK 代替他机完成。各来源保留在原任务目录和 Git 历史，不重复复制进技能。

技能安装发现的并发回滚和正式配置快照误识别已修复：安装使用跨进程互斥，只回滚本次实际发布且字节未变的目录；AGENTS 原子替换。只有 node-<n>/node-<n>.toml 是当前正式身份，历史配置快照不能算另一个节点。操作说明见 [安装流程](../INSTALL.md)，不用服务重启来激活技能。
