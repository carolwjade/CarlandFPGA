An asset with `source_license={}` emits `Invalid call. Nonexistent 'String' constructor.` at line 80. Fixture `fixture-bad-license` changes only water's returned metadata; `negative-bad-license` exits 1, 14 assertions / 7 failures, preserving the exact stack trace. **F2 — P2 — Wrong static factory signature produces a fallback while status remains ready.** `_ensure_factory` at `viewer/asset_presenter.gd:35-42` checks method names and static flags only. Changing the factory signature to `create_obstacle(kind: String, required_argument: int)` passes that check. The call at line 61 emits `Expected 2 argument(s)` and returns from the function before lines 68-72 can record a failure. Reconciliation supplies a greybox, but `report()` at line 224 sees an initialized factory and empty diagnostics and returns `ready`; the shell says resources loaded. `negative-signature` exits 1 with 10 assertions / 3 failures and the real runtime stack. Inspect callable argument signatures before use and record degraded state before calling an unproven factory; only mark success after a returned asset passes validation. Runtime errors must remain visible in engine evidence.

**F3 — P2 — Empty Visual nodes are adopted with stale metadata and silently lose geometry.** `_validate_asset` at `viewer/asset_presenter.gd:78-96` checks that Visual/Collision are Node3D and that metadata describes a positive volume, but does not verify any renderable geometry exists. Removing every mesh child of water's Visual after B finalization leaves valid-looking metadata and passes the entire validation. The actual editor shows only the ordinary water label and no water mesh, no greybox, empty diagnostics, and `ready`. `negative-empty-visual` exits 1 with 14 assertions / 7 failures and no unexpected script errors. Check the actual Visual subtree for nonempty valid mesh geometry during creation, and reject missing/incompatible render data before registration. This check runs at creation rather than on transform updates. The pinned normal five-kind meshes remain intact; this is the promised invalid-asset failure boundary.

**F4 — P2 — Fallback labels and selection ignore the parent transform.** `viewer/main.gd:639-649` constructs fallback bounds in document-local coordinates and assigns them as global label coordinates; `main.gd:339-343` intersects a world ray against the same local document bounds. With a rotated/translated `_world`, the fallback mesh itself moves correctly but its label remains at the old location and clicking its displayed centre misses. The valid-asset path correctly handles this transform. `negative-null` reproduces both failures (16 assertions / 2 failures): actual label `(2.000001, 5.7, 3.999999)`, expected `(10.67287, 7.7, -1.448521)`; `_pick_object` gives `-1` instead of ID 1 at the displayed mesh centre `(10.67287, 5.0, -1.448521)`. Compute bounds with the full fallback global transform and transform world rays into fallback-local space while preserving their world parameter. This is conditional on the transformed-parent contract; the shipped scene currently uses an identity parent, so this is not claimed as an ordinary identity-scene mouse failure.
