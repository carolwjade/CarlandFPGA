# HIL request tracker API resolution

The main-selected plan is ../next-software-main-20261020/hil-request-design-plan.md. This is a diagnostic association component, not a sender, authority, measurement authenticator or HIL executor. Three assigned new product paths only; mailbox is read-only and never imported.

`HilRequestTracker(run_id, dependencies=None)` is owned by its constructing thread. `HilDependencies` supplies explicit `verify_boot(event)`, `verify_observation(raw, boot)`, `verify_timing(raw, boot, original_request)` and `verify_capture(raw, boot, original_request)` methods. No permissive provider exists. Frozen result dataclasses retain exact original BOOT/request/raw associations; they are not credentials. Source/clock/capture authenticity and nonoverlapping measured delay meanings remain upstream obligations. None is unknown and cannot qualify an association.

`boot(event, now_ns=...)` replaces the previous activation with STOP before calling the verifier. A returned strict same-run BootBinding carries immutable existing sealed context, increasing generation and an original source identity (None remains unknown). Only topology1 HIL is accepted; PC_DIRECT is refused, never recast as capture. At most64 used/proposed sessions are remembered, with refusal on exhaustion. A structurally valid verified proposal is retired before the final veto fence, so caught STOP/reentry cannot make it reusable. New BOOT resets per-session request/observation/response high waters, not the used-session/generation history or host clock high-water.

`observe(raw, now_ns=...)` validates CRC/schema/active context and the verifier's exact original source association/sample lower bound; at most four same-activation TELEM/EVENT references are retained. Unknown source/mapping does not admit an observation. Receipt/completion time never replaces sample acquisition. Same raw duplicate does not renew; conflict, backward/half-range/wrap requires STOP/fresh session.

`request(packet, first_send_ns=..., now_ns=...)` accepts only wire CONTROL3D14, CONFIG5 and GAIN10. Non-motion types retain identity/bytes only and cannot qualify. BOOT wire exchange belongs to verify_boot and is not admitted here. CONTROL3D parses the existing16-byte payload, session/cmd_id/header.seq/config epoch, STOP zero-field rule, bounded TTL, speed and quantized curvature. The immutable OriginalRequest stores `(session,type,seq)`, first raw packet, semantic payload, first-send, original TTL, original observation reference/sample and target codes. Entry separately stores only the latest received raw retry. Same payload may have a different tick/CRC but retains original time/deadline; changed payload rejects. History is16 entries; three per-type nonwrapping sequence high waters protect eviction. Different request types have different keys. Superseding CONTROL3D retires the old command. STOP latches the activation; expiry/eviction permanently retires that request, while a new command may use new valid evidence.

`response(raw_board_response, now_ns=...)` uses existing host validator before callbacks/state mutation. ACK3D must bind type14/request_seq; STATE3D must bind last_control_seq/current request. Other board responses, including STATE8, are diagnostics only. Captured phase3, fault0, quality15, exact target codes, current independent capture/BOOT/request/batch and strict timing evidence are required. The existing validator already requires response control_epoch==active context.config_epoch: preserve that strict frozen rule rather than invent a second domain. A changed/wrapped epoch needs a new verified session. Capture sequence is nondecreasing without wrap. Changed duplicate response identities and backward/half-range sender sequence fail closed; an exact wire repeat cannot renew, even with a new receipt envelope.

Deadline is exactly min(original first-send+TTL, receipt.lower+max(0,current remainingTTL−serialUpper−usbProcessingUpper−clockErrorUpper), original sample lower+FAST1500ms/STRESS12000ms, previous deadline). Receipt.lower is conservative. Equality to now expires. No new observation/retry/ACK/STATE can increase a request deadline or resurrect retired requests. Unknown original observation remains unknown even if a later observation arrives. `check(now_ns=...)` returns the current frozen Association diagnostic; `snapshot()` is detached bounded state. A qualified association is still not send/motion permission.

All time-taking methods use strict nonregressing host integers. Public wrappers catch malformed call shapes before a trusted callback can catch them without recording a veto. Reentry invalidates the in-flight transition. STOP is always permitted and changes veto generation; verifiers are fenced immediately on return and before publication. Exceptions fail closed. Foreign-thread calls set a pending STOP for the owner and reject; providers may not do asynchronous/reentrant admission. A malicious trusted verifier hiding internal failure or fabricating original evidence is outside the valid provider contract, not made trustworthy by dataclass type/hash/boolean.
