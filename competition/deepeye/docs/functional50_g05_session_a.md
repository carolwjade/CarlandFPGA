# G05P session v2 (candidate)

This is an in-process, one-use session for a real original `TransactionIssuer`, its canonical TRACE/G05 port objects, registry, device, loader thread and boot. It grants no BOOT_ACK, STATE8, source freshness, physical stop or motion authority. Root must separately select and qualify any physical operation, pair, pins and actual producer, and preserve all H01–H15 gates.

Construct `G05SessionV2(issuer)` with the original unused issuer and exact existing `Limits`: at most two commands, at most 64 status reads for this session, one fixed prospective board-monotonic duration at most 10 seconds. `init(identity_words13)` binds this deadline once, stages one original identity, issues one BEGIN, then reads and compares all 13 original identity words and actual status/fault. It can complete before any command is known. `apply_one(command_words7)` validates before effect, rereads original identity, stages/commits the actual one command, performs bounded actual status/fault polling, LATCH, the original 32-word read and RELEASE. `observe_status()` rereads actual identity/status/fault. Explicit status-read accounting includes the fixed 197 high-level methods' internal status reads; this accounting depends on the separately pinned 197 implementation. `close(stop=False)` retires only the software session. `close(stop=True)` may issue at most one STOP only while the session is still active; it then reads status/fault, but neither establishes electrical or physical stop. Unknown/failure forbids any future STOP, retry, command or observation; default close can retain failure evidence.

`SessionFacts` is frozen, with schema `g05_csr_session_v2`, kind `init`/`apply`/`status`/`close`, original operation and G05 policy IDs, board deadline selection and absolute deadline, original 197 I/O phase first/last indices (None for a no-I/O phase), actual identity words, actual status/fault when read, optional original `CaptureFacts` of 32 raw words, cumulative `IOReceipt` original started/returned bytes, `unresolved_receipts` and state/authority. `UnresolvedIO` retains the real original started, returned and not-attempted file bytes where present, and None where absent; it is evidence of an incomplete/unknown high-level call, not a completed result. A failure cannot create success facts. 32-word capture data comes from actual port reads; submitted values are used only for association checks.

No supplied clock callback exists. 207's board-monotonic deadline is never renewed, and 197 checks it after durable started and before each actual MMIO. It is not a hard in-call timeout; a blocked/lost MMIO remains unknown and must not be replayed. Host QPC belongs to a separate transport layer. The cumulative raw receipt theoretical upper bound can be large: 197 total_io<=2048 and each retained file is bounded to 4096 bytes, up to three raw files per unresolved I/O. A transport must explicitly bound and preserve its own full receipt encoding and storage; hashes alone are not those bytes, and a 4096-byte response line is insufficient in general.

Five NEW pure software controls exercised a synthetic MMIO through the actual issuer/port, initial no-command BEGIN, two later commands, actual-value 32-word snapshots, one-use behavior, default versus explicit STOP, deadline rejection, status-read budget and retained partial unknown evidence. No prior seven controls, board, SSH, PYNQ, PDE or model were run. Synthetic inputs and timing are not an acceptance result; actual command provenance, board latency, causal sources and final gates remain unproven.
