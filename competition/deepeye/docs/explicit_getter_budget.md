# Explicit endpoint getter budget for new value construction

`ValuePolicy.getter_endpoint_cap_m` is an optional immutable `Fraction`, default `Fraction(0)`. `_construct_values` accepts only exact Fraction values from 0 to 1/100 metre inclusive, with numerator and denominator each at most 256 bits; other types, negative, larger or resource-excessive values cause `ConstructionRefusal` before geometry work. A later caller can construct a new policy with `dataclasses.replace(policy, getter_endpoint_cap_m=Fraction(1, 100000))`; this does not activate that policy or admit a getter.

For zero, the original ValuePolicy canonical serialization and policy digest are preserved, as are existing geometry identity, scene digest, budget and behavior. For a nonzero cap, the canonical policy encoding contains `__getter_endpoint_cap_domain__` with value `DEEPEYE-ENDPOINT-AFFINE-SET-GETTER-CAP-V1` and includes the exact cap; budget provenance also carries `endpoint-affine-set-v1:<numerator>/<denominator>`. `BudgetDerivation.getter_endpoint_cap_m` records the exact value. The cap denotes only endpoint affine-set displacement allowance, not native continuous pose, child CPU evaluation, GPU, physics, full visual-body correspondence, board or H03 acceptance.

Existing asset and obstacle terms remain unchanged, including their existing guards. Numeric becomes `GUARD + getter_endpoint_cap_m`, with no borrowing of a previous guard and no second asset charge. The original rational total is outward-exported with `_upper_float`; existing full initial capsule scene, corridor, workspace and passage checks run for the newly constructed total and can reject the world. The cap is part of initial immutable construction, not a post-CAS edit. A later independently reviewed admission must compare the Task61 actual endpoint bound against this preallocated cap, retain custody and all other original fences, and explicitly handle post-effect failure. No such admission is introduced here. Existing 100 ms and final acceptance requirements are unchanged.


Policy commitments must use alues._digest(policy) directly for both freeze preparation and construction. Canonical packing validates the cap type, range and size before encoding or hashing, including malformed values equal to zero. This component alone does not retain the freeze commitment or compare it against a later construction; that lifecycle check belongs to the world owner. Compatibility is established for zero-policy canonical bytes/resource count and the tested default policy, geometry, scene and budget outputs; adding the defaulted cap metadata to BudgetDerivation changes its generic packed representation.
