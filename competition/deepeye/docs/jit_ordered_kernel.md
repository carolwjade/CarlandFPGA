# Strict serial JIT source kernel candidate

`strict-jit-ordered-v1-candidate` is inactive and not wired to a source, acquisition scope, controller, BOOT, timestamp, profile or RNG. It accepts trusted Root-private compiled tuples and original warmed rows; this convention is not a security boundary. `_prepare` binds a snapshot of one field to typed arrays; discard it on any field mutation. It does not cache poses or authorize motion. `_raw_sums` returns five ordered weight and weighted-conductivity sums or None; `_channels` keeps original Python `math.log10` and differences. The original forward profile, source ledger and field remain unchanged.

The serial njit path uses `fastmath=False`, `parallel=False`, separate operations, literal three-finite-product CPython 3.12.14 `math_fsum` expansion/half-even correction and original row/piece priority order. It never accepts a caller-provided sampler. Cylinders and unsupported numeric cases take complete original scalar fallback. `_safe` checks world coordinates, deltas and local products against its finite [1e-80,1e80] nonzero domain; it does not validate every world partial, row, weight or sigma. The original trusted table and field constructor remain essential. Boundary/unknown samples return None according to the original traversal. Scalar fallback re-evaluates the full pure kernel; it is appropriate only for trusted immutable inputs, not side-effectful callbacks. There is no general proof for this numerical domain, floating-point mode, Numba runtime, reentrancy or platform. Source ledger own-slot/no-backfill, actual fresh timestamps, exact live Root custody, and independent activation controls are not implemented here.

NEW Task64 controls in test_jit_ordered_kernel.py compare finite sum values, subnormal/overflow fallback, point and sums for overlapping rank/ties/unknown/boundary/cylinder/256-piece cases, and seeded independent original codeobject EM/ADC/RNG progression. Actual saved two-object field has three additional bounded bitwise channel comparisons. The stored actual LLVM IR and assembly of one compiled signature contain no detected fast/reassoc/contract flags or FMA instruction (see Task64 evidence); this scan is specific to that runtime, CPU and signature, not proof for other systems. Source: CPython 3.12.14 `Modules/mathmodule.c` lines 1165–1187 and 1289–1361, https://raw.githubusercontent.com/python/cpython/v3.12.14/Modules/mathmodule.c.

Numba 0.68.0 and llvmlite 0.50.0 are project-local dependencies; primary NumPy 2.3.5 and CPython 3.12.14 were used. Install provenance, licenses, wheel hashes, binary/module pins and bounded supervisor receipts are in Task64 evidence. No performance or equivalence assertion is made beyond those observed cases; actual integration, concurrency and source-book scheduling require independent review and separately authorized operations.
