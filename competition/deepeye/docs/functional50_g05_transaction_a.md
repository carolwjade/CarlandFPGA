# Original G05P transaction issuer (candidate)

`TransactionIssuer(trace, port, Limits(max_commands, max_polls, duration_ns))` accepts only the canonical original same-process `functional50_board_a._TracePort` and `functional50_g05_a.G05Port` returned by the same actual loader/factory, with the same private registry, device, process, boot and thread. Both objects remain strongly held; only one issuer may claim a G05 port. The limits are exact integers: 1–16 commands, 1–1024 total status polls, and a positive duration no greater than 10 seconds. Root separately selects/qualifies actual board operation, pair, electrical pins, source, original G05 policy, PC authority and final gates. Construction grants none of them.

`issuer.run(identity_words, commands, stop=False)` is one-use. It checks all 13 identity words and all command words before effects, durably records the start, binds one fixed, nonrenewable prospective board-monotonic deadline, stages identity and issues one BEGIN, then reads all 13 original identity registers and checks them against the selected identity. For each bounded command it stages/commits once, polls actual status/fault within the selected total poll/deadline budgets, then latches, reads the original 32-word capture, checks its actual command/tag association, and releases the latch. No later command is replayed after a failed or unknown effect. The default does not issue STOP. `stop=True` explicitly selects at most one STOP after all captures and then reads actual status/fault; a returned STOP/write or status is not physical stop proof. No STOP occurs automatically on an error, unknown result or deadline.

The returned frozen `TransactionFacts` has `schema='g05_csr_transaction_v1'`, `operation_id`, `policy_sha256`, the 13 **actual read-back** `identity_words`, `captures`, `deadline_selected_lower_board_monotonic_ns`, `deadline_board_monotonic_ns`, optional actual `stop_status`/`stop_fault`, original per-I/O `receipts` and `authority='not_evaluated'`. Each frozen `CaptureFacts` includes actual status/fault before latch, all 32 original latched words, snapshot status brackets, actual result sequence and `tick_unit='50MHz_cycles'`. Capture data is read from the port; submitted command words are used only for association checks. Each `IOReceipt` keeps exact bytes of the original started and returned G05 word-operation files. Neither board-monotonic brackets nor 50 MHz cycle counts are host QPC or physical-arrival bounds.

The issuer checks its deadline after its own durable intent and before each high-level port call. The optional G05 port deadline is bound exactly once and is never renewed: every internal MMIO call records started, checks the same board monotonic clock after that record and before touching MMIO, and, when expired, records not-attempted and permanently fails closed. A returned MMIO call is still recorded even if it returned after the deadline. There is no in-call hard timeout; a hung MMIO or lost return remains unknown and is never replayed. If a transaction raises, original files remain under the claimed G05 directory and no `TransactionFacts` success object or automatic STOP is invented.

The pre-existing G05 API behaves as before if no issuer deadline is bound. Seven new bounded software-only controls include synthetic original port/MMIO state and deadline-after-intent, one-use, explicit/default STOP, and immutable type checks. They do not prove a real load, physical capture, BOOT_ACK, STATE8, sensor freshness, QPC mapping, H12, timing or final acceptance. The physical board, real SSH, PYNQ and prior suites were not run.
