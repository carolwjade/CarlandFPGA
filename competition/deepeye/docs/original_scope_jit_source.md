# Original-scope JIT source integration (default off)

`root_strict_jit_ordered_kernel_v1` is a separate opt-in plan profile. Existing plans do not import NumPy/Numba through this branch. The enabled source-only runner requires the original EM scope and original source book, exact fixed helper/core source pins, fixed canonical manifest identities and full per-file hashes over the exact project-local Numba/llvmlite target and the primary runtime NumPy trees. It refuses a pre-imported numerical package, wrong versions/origins, inventory differences, or a loaded LLVM DLL whose actual Windows module path differs. `source_paths(True, dependency_config)` includes helper/core and manifest-listed dependencies. This is provenance and admission inside the trusted process, not an OS security boundary.

After those checks, the readonly-array JIT signature is compiled and scanned for floating fast/reassoc/contract/FMA before Root creation, source-book baseline and source origin. Actual Root field pieces and original warmed weight rows are then copied to immutable bytes-backed arrays and hashed. An exact original factory/source/profile/clock/native association is required; backend invocation checks active single-use scope, original consumed tick/count and owner thread, field/root identity and frozen generations, matching original normalized committed pose bits, and array identities/hashes. The scope's existing pre/post owner polling and root checks remain in force. The same original `ForwardProfile.acquire_em` code object runs in a fixed isolated FunctionType globals dictionary whose kernel reference alone is substituted; original instance, bound `sample_adc`, RNG, filter state and timestamps are not replaced. Unsupported numeric/field status falls back to original `_kernel_channels` with the same active sampler and already-consumed slot, before any EM noise. No arbitrary sampler or provider is accepted and no motion authority is created.

The software backend is a separate exact type whose factory must be the explicitly marked software path and must reject actual Root/native custody. Its controls do not establish production Root operation. The 20-record opt-in limit is confined to the JIT profile; default legacy record limit remains 16. Existing 100 ms age and no-backfill rules are unchanged. Any loss, tampering, reentry, mismatch or exception fails closed and retains original exception precedence.

`_FrozenEpoch` now retains the exact model-policy hash from its own completed freeze request. Thread-checked pre-entry validation rejects malformed freeze hashes and rejects any policy whose `values._digest(policy)` does not match that current, nonretired original epoch, before constructor/native-send/executor effects. This check does not invent a new policy digest or relax any nonzero cap; Task70's final canonical policy implementation must be reviewed and tested together before an actual release.

Task69 controls are software-only. The primary-error/partial-book test uses a marked software stub because the existing software book fixture cannot bind a production-only scope; it is not evidence of live RootSourceBook behavior. Correctness across every floating-point input, timing overhead of per-acquisition array hashing and original live book cadence remain unproven. The proposed 20-record plan is deliberately a template, not a staged or approved native run. No 100 Hz, C3, board, G03, R03, all29 or H12 acceptance is claimed here.


## Scanned-signature lock

The readonly signature scanned at startup is now the only allowed compiled overload. Warm-up requires a fresh unspecialized dispatcher, compiles and scans exactly one signature, retains its actual compiled entry point, and disables further specialization. Before source start, backend construction checks the actual complete field/row arrays against that signature. On every kernel invocation the private guard checks the fixed dispatcher, locked overload and entry-point identities, disabled compiler, all array dtypes, ranks, shapes, C layout, alignment and writeability, plus exact `numba.typeof` argument types. The source path calls that saved compiled entry point directly; a mismatch is a fault rather than an invitation to compile. Fixed immutable-array identities and hashes are also checked. Original cylinder/status-2 scalar fallback is retained after the same signature gate, without reusing or retiming a source slot.

Task72 NEW software controls checked the prepared arrays from the saved two-object snapshot, dtype/layout/unaligned/writeability refusal, no new overload or re-warm, disabled compiler error, entry/dispatcher replacement, same-bytes array substitution, reentry, original codeobject/RNG/ADC equality and cylinder/status-2 fallback. Their passing result is not an actual Root source acquisition or proof of all runtime behavior. Each future native process must compile and scan its own exact signature and preserve resulting provenance. Root must update `_CORE_SHA` only if it intentionally normalizes the core after this task, with the planned AST/byte evidence and fresh final manifest; this task leaves the original raw `5ba0aab9…` pin intact.
