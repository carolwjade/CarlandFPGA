# Ordered NumPy field batch candidate (inactive)

`ordered-numpy-field-batch-candidate-1` is private and unconnected to the producer, authority, scope, controller and plan activation. Trusted Root-process immutable compiled tuples are a convention, not a security boundary; the kernel returns only three raw channels or None. No arbitrary callback is accepted.

For box fields, separate NumPy float64 operations compute point-minus-centre and three rounded matrix products. `_fsum3` translates CPython 3.12.14 `math_fsum` partial expansion and final half-even correction, with separated array operations. Pieces are traversed in their original sequence; lower-priority later boundaries still invalidate, strict greater-than updates priority and unknown sigma may be superseded later. The first invalid source value is returned as None by the enclosing kernel. The original scalar `_sample_sigma_pure` performs complete point traversal for cylinders, nonfinite/out-of-range points or products and unsupported numeric types. Fast-path nonzero operands are confined to [1e-50,1e50]; this is a deliberately conservative operational restriction, not a proven platform-independent equivalence bound. No guessed geometric tolerance or skipped piece is used.

Source reference: https://raw.githubusercontent.com/python/cpython/v3.12.14/Modules/mathmodule.c lines 1165-1187, 1289-1323 and 1334-1361. IEEE binary64, round-to-nearest-even and no reassociation are necessary assumptions. NumPy float64 loop behavior, interpreter and CPU rounding mode, subnormal handling and finite-domain error bounds still require independent proof and runtime admission. The batch computes later pure points before the enclosing kernel observes an earlier invalid point; its semantics are restricted to trusted immutable original table rows and pure compiled fields, never external callbacks or observable side effects. The candidate is default-inactive; passing limited differential inputs is not full v1 equivalence, a performance claim, actual source freshness, board result or acceptance. It remains unapproved for integration.

The new Task56 test file directly compares source scalar field bit patterns/None including rotated boxes, priorities, equal ties, unknown and later boundary, 0/256 pieces, epsilon, nextafter, nonfinite/extreme and cylinder fallback. It checks translated three-value sums against `math.fsum` including cancellation and halfway cases, coordinate bits, five separate seeded ordered accumulations, and independent seeded same-codeobject profile/ADC/RNG. Other inputs and exception-order scenarios require further scrutiny. Task51 tests were not rerun.
