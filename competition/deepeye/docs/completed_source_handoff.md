# Completed source handoff

The original pump defaults to its previous behavior. After binding the original RootSourceBook and before `start`, trusted Root may call `enable_completed_sample_handoff()` once. A completed `poll()` holds one bounded canonical-byte snapshot, its actual payload object, and the actual token issued by that Book. A poll while that slot is held is rejected without consuming another source tick.

After poll returns, the original thread calls `claim_completed_sample(payload)` with the identical payload object. This checks the same Book, running source, original thread, idle poll, and unchanged bytes, and returns the actual one-use token. Use that token at the real capture point, such as `ProjectionSession.observe_capture`. After use, call `release_completed_sample(payload)`; it checks the payload again before releasing the slot. A copied or modified payload, repeated claim, or modified payload at release is rejected. Comparisons detect changes present at the two checks; a caller that changes and restores a mutable object between checks cannot be detected by snapshots. This is trusted-process custody, not a security boundary.

For a recorded completed transition already attached through `ProjectionSession.observe_finished_transition`, call `poll_after_finished_transition(session, transition)`. It returns `None` until the real source clock reaches the first origin-relative 10 ms boundary at or after completion; once reached it performs the original poll and returns `(payload, token)` or `None` if no new tick exists. Release the payload after capture. The latest original completed transition, original session, and book binding are required. This helper never sleeps, changes the source origin, supplies a new timestamp, backfills, or promotes an old EM sample to fresh. An EM observation older than 100 ms remains invalid until a real later EM acquisition.

The software-only `_CausalSourcePump` fixture seam is separate from the exact production pump and RootSourceBook. These APIs grant no BOOT, dispatch, movement, board, or admission authority. Original session and record limits remain in force. Software controls are not evidence of a native Root integration or acceptance.
