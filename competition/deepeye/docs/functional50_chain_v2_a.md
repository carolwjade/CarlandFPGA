# Functional50 explicit multi-cycle chain, v2

This is an A-owned prospective transport. It does not authorize loading,
claim a board result, or replace final acceptance. One selected load, process,
TRACE port, G05 mapping and QPC owner remain bound for the session. The fixed
entry is `functional50_chain_v2_board_a.py chain_v2 PLAN
chain-v2-board-manifest.json MANIFEST_SHA256 G05_POLICY`. Its exact manifest is
generated by `make_manifest_bytes()` from the selected absolute snapshot;
the receiving side verifies every fixed file before load. The SSH SessionSpec
must explicitly choose `functional50_chain_v2` and its v2 manifest and entry.

Requests are canonical JSON lines with exactly `schema`, `id`, `operation_id`,
`kind`, `payload`; schema is `functional50_chain_v2`. IDs are one-use. Init
uses exactly `identity_words` (13), `max_commands` (1..2), `max_polls` (4..64),
`duration_ns` (1..10000000000), `max_io` (1..450). It performs real G05 init
and identity readback with no command. The G05 policy's total I/O limit must
cover `102 + 76*max_commands + 2*max_polls` yet not exceed `max_io`.
That deliberately conservative upper bound covers factory and init (39),
each apply (76), four fresh statuses (60), optional STOP observation (3),
and up to two I/Os per selected poll. The fixed journal records each contain
bounded IDs, uint32 values/PID, uint63 clock values; the entry enforces <=512
bytes for each retained original record and a prospective `40960+2176*max_io`
reply bound. It neither truncates nor calls a larger reply successful.

After init, `trace_scan` accepts exactly the original B131 `request_hex`,
`source_hex`, four `companions_hex`, `build_binding`, and explicit `max_io`
(1..2000); at most two scans. `apply` accepts exactly `command_words` (seven),
at most the selected number and at most two. `status` has an empty payload and
may be selected four times. `close` has exactly `stop` (boolean), defaulting
to false in the host API, and is one-use. Scans and applies can be interleaved.
The original reducer checks the actual previous hardware tag before ARM.
Both scans share the original global TRACE 5000-I/O and 4096-POP budgets.
The scan owner binds once to the G05 board-monotonic deadline and checks it
after the started journal is synced and before each TRACE MMIO operation.
An in-flight MMIO call has no asserted hard interrupt or completion bound.

Responses have exactly `schema`, `id`, `operation_id`, `kind`, `status`,
`result`, `error`, `unknown`; the limit is 1 MiB. Successful G05 results carry
actual cumulative started/returned raw receipts as lowercase hex and actual
phase boundaries, plus original snapshot words. Successful TRACE results
carry the original batch wire/result, board correlation status, unique board
evidence directory and evidence-manifest hash. The full original TRACE I/O
files stay in that directory: a hash is not a host readback. The host separately
correlates the returned wire to its original B131 request and companions.
Host QPC lower/upper bounds wrap the entire request/reply; they are separate
from board monotonic timestamps. No response claims BOOT acknowledgment,
STATE8, physical stop, source equivalence or acceptance authority.

After uncertain effect or malformed/incomplete reply, the original host
session becomes unknown; no resend, further scan, automatic STOP or replacement
process occurs. If the G05 session itself entered FAILED, the board entry makes
at most one `close(stop=False)` call solely to collect existing journal bytes;
it performs no MMIO and reports `CLOSED_AFTER_FAILURE` under UNKNOWN. If this
collection fails, the unknown response has no facts and original files remain.
Local process cleanup is separate and cannot prove a remote physical stop.
