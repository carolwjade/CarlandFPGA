# A-only functional50 load and TRACE port (candidate; independent review required)

`functional50_board_a.py` imports no PYNQ or hardware at module import. The operator invokes it only after Root has independently fixed an explicit new operation, same-build BIT/HWH/mapping and request, verified physical exclusivity, new BOOT/current SDK08 stop status, wiring and board environment. A plan or boolean is not permission or proof. Do not invoke an old/unknown operation again. GPIO/pins can change when PL is loaded even if this entry never writes G05; Root must resolve electrical/wiring safety before any load.

Plan JSON has exactly these keys: `operation_id`, `request_sha256`, `build_id` (32 lowercase nonzero hex), `source_commit` (40 lowercase hex), `boot_id` (canonical UUID), `bit_path`, `hwh_path`, `mapping_path`, `bit_sha256`, `hwh_sha256`, `mapping_sha256`, `operation_parent`. `request_sha256` is SHA256 of UTF-8 `json.dumps` of all remaining keys, with `sort_keys=True,separators=(',',':'),ensure_ascii=False`. This request checksum binds the submitted plan bytes logically; it does not authenticate its issuer or certify same-build provenance. `mapping` must match selected B functional50 BD_MAPPING structure: BD/top/master/build_id and ordered G05/TRACE windows with exact instance, VLNV, base, range. Source commit and hashes must be cross-checked against the externally reviewed same-run build closure and qualified timing/manifests; this script does not establish that correspondence.

The BIT and HWH must be absolute same-directory same-stem files, distinct regular single-link files; mapping is a third distinct file. The input scanner rejects symlink paths, oversized, changing or hash-mismatched inputs and duplicate JSON keys. It validates the selected HWH's 2026.1 PS/endpoint identities, FCLK0 parameters, disabled other ports, TRACE BUILD_ID, exact GP0 4KiB disjoint windows, 32-bit AXI-Lite metadata and the two endpoint clock connections. This is a **subset** of B's full `verify_functional50_hwh.py`: it does not independently certify the complete reset/interconnect/external pin topology, timing, source closure or other build gates. Root must independently review those artifacts and same-build hash evidence before use.

In a new operation directory (creation is exclusive), it records a started marker and copies the approved BIT/HWH into new unique operation paths. It uses actual `RuntimeMetadataParser(Metadata(input=hwh))`, `_create_xclbin`, `_unify_dictionaries`, `XclBin`, `refresh_hierarchy_dict`, and actual bit2bin; it does not unpickle a previous parser cache or call `Overlay.download`. It checks parser IP metadata, confirmed root/armv7l/BOOT and current kernel `ps_clk=50 MHz`, PS source 0, IO PLL FDIV20 and FCLK0 dividers 5/2. It exclusively creates a new unique firmware file, records clock-write intent, uses `Clocks.set_pl_clk(0,div0=10,div1=2)`, reads actual PS registers back, and verifies FCLK1–3 control words unchanged. Then it records load intent and calls `Bitstream.download(parser=parser)` on the same exact EmbeddedDevice. PYNQ can write global metadata/cache, FPGA manager and XRT state during load; no previous cache is deleted or restored by this entry. Clock and load started/returned are distinct: a failure or missing return is not proof of no effect. No automatic rollback, retry, extra clock setter, cleanup or old-operation adoption is performed.

After actual successful load return and PS readback, the same process maps the actual TRACE aperture and reads identity words and four little-word BUILD_ID words. Only then is the private TRACE port issued to that process. `read32` / `write32` use fixed host103-derived aligned offset whitelist and per-request unique IDs; writes are limited to TRACE, never G05. Command `5` is CANCEL and `8` is FIFO POP. A command quota bounds ARM to one, PUSH/BIND/ACK to four each, CANCEL to one after an ARM attempt and POP to 4096, with 5000 total register calls; this port is not the transaction/reducer or a source/BOOT authority. It does not implement B's pending actual adapter or infer cleanup success. Each call records exclusive started and returned files. A hanging MMIO call has no in-call timeout: host timeout, process cancellation or SSH loss cannot establish whether a write occurred or whether hardware/remote execution stopped. Preserve the original operation and unknown state; no automatic retry or duplicate executor.

CLI: `python3 functional50_board_a.py /absolute/plan.json`, then newline-delimited request objects `{ "id": "unique-id", "kind": "read"|"write", "offset": integer, "value": null|uint32 }` on stdin; each response is a JSON line. Operations are confined to the one port returned after this process's own load. Do not send requests from a different process or substitute a pre-existing device handle. The Python-private boundary is not a hostile-code security boundary. Owner must perform appropriate STOP/CANCEL and evidence collection with the actual source/adapter contract; never infer success from mere returned calls.

The 5000-call port budget covers the normal single-scan maximum of 252 bytes. It does not cover draining every byte of a possible 4096-byte abnormal retained FIFO: the reducer needs five calls per byte. If that budget is exhausted, retain the confirmed prefix and remaining/unknown state; do not report complete collection or recovery. A larger recovery transaction needs its own explicit finite budget.

Only four NEW pure tests were run using synthetic structural XML and word/JSON/clock boundary data. They do not execute PYNQ, hardware, MMIO, vendor tools, real HWH or actual board flow. Full parser construction, current 2026.1 HWH shape, device identity, correct BOARD/XRT environment, firmware/cache side effects, clock setter behavior and BUILD_ID are still unverified on the board. No source-age, live source, H12, G03/R03/all29 or timing acceptance follows.
