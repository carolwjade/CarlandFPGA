# Optional same-load G05P port (candidate)

The original loader remains TRACE-only by default. It now retains the actual returned `_TracePort`, exact same embedded device and MMIO class, HWH-validated two apertures, original parser/HWH bytes, boot/process/thread and immutable five-field plan binding in a private same-process registry, after TRACE identity/build readback. This registry is in-process custody, not an OS security boundary or proof of a qualified physical build. No G05 map or read is performed merely by the loader.

A future Root-owned Python entry may import the same `functional50_board_a` module, call its original `open_from_plan`, and then call `functional50_g05_a.open_g05(returned_trace, absolute_policy_path)` once in that same process and thread. It must not run the loader as `__main__` and separately import a second module instance, since that would be a different registry. Current TRACE-only CLI and stdin format remain unchanged. Root separately owns the qualified pair, new physical operation, pin/electrical wiring, external capture and actual stopped-state decisions.

Policy is a new separately supplied regular single-link file, with exactly `binding`, `limits`, `policy_sha256`. Binding has exactly the loader's `operation_id`, `request_sha256`, `boot_id`, `source_commit`, `build_id`. Limits have exactly `begin`, `commit`, `stop`, `latch`, `release`, `total_io`; each is an integer in 0..1, 0..16, 0..1, 0..16, 0..16, 1..2048 respectively. `policy_sha256` is SHA256 over `json.dumps({'binding': binding, 'limits': limits}, sort_keys=True, separators=(',', ':'), ensure_ascii=False).encode('utf8')`. The policy digest is not authorization. The exact file bytes are saved in a new G05 operation subdirectory; creation/mapping is one-use and recorded before/after. A failure after started is retained unknown and cannot be retried.

The factory validates same original trace object/device, HWH-derived disjoint G05/TRACE apertures, boot, pid and loader thread; maps only G05; then actually reads G05P magic/layout and initial status/fault. `G05Port` exposes `read32(offset,id)`, `stage_identity(words13,id)`, `begin(id)`, `stage_command(words7,id)`, `commit(id)`, `latch(id)`, `read_snapshot(id)`, `release(id)`, `stop(id)`. Every ID is unique in the G05 port; every actual word I/O gets a separate durable started/returned record. All writes go through these fixed methods; no CLEAR/RESET or arbitrary control word exists. Quotas and total I/O are separate from TRACE's unchanged 1 ARM/5000 I/O limits. Private fields/methods are trusted-process conventions, not a hostile-code boundary.

Identity words are eight uint32 run words, four nonce words and one nonzero session word. Command words are uint32 representations of signed 16-bit yaw, pitch; profile; speed; TTL ms; increasing nonzero command ID; tag. The mapper validates exact G05P candidate ROM and profile bounds; this is not motion authorization. BEGIN requires all identity words and actual unbound status, COMMIT requires all command words and actual live/no-pending/no-inflight/no-latch status, LATCH requires an actual eligible result, RELEASE requires a held latch. STOP is one explicit possible control operation; a returned write alone does not prove retirement or electrical stop. Returned snapshots retain the 32 raw latched words and status/sequence brackets with cycle counts in 50 MHz units. They do not claim an atomic native/physical interval, host QPC equivalence, fresh source, a BOOT_ACK, STATE8, or authority.

Original intent and returned MMIO records are separate. An exception after a call starts permanently fails this port and forbids replay or further calls; a hung MMIO has no in-call deadline. The claimed operation and original port are retained even if later identity checks fail. No automatic rollback, cleanup, fabricated status or board approval is provided. Five new bounded software-only controls include a synthetic MMIO state-machine fixture and unknown-effect refusal; no PYNQ, SSH, RTL, physical board or model ran. Independent source and safety review and a newly selected physical scope remain necessary; all H01–H15 gates remain unchanged.
