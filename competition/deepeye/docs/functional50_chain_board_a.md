# Same-load TRACE/G05 chain entry

This entry is disabled unless explicitly invoked as `python -I -B functional50_chain_board_a.py chain_v1 PLAN chain-board-manifest.json MANIFEST_SHA256 G05_POLICY`. A fixed complete file manifest is verified before importing product modules and again before original board load. The original loaded `functional50_board_a` canonical package module and its one TRACE port are shared by the existing G05 factory and issuer; no additional board loader or device is created by this entry. Root must independently select and verify the full remote file manifest, original plan, G05 policy and physical operation.

After same-load binding and exact plan/policy readback, ready includes separate plan file SHA, load request hash, source commit, build ID, policy file SHA and manifest SHA. The entry retains original plan and policy bytes in the operation directory.

Input envelopes use exact canonical JSON `{schema,id,operation_id,kind,payload}` with schema `functional50_chain_v1`. At most two are read: optional first `trace_scan`, then one `g05_transaction`; G05 alone is permitted. TRACE payload has request_hex, source_hex, companions_hex and build_binding. G05 payload has identity_words, commands, stop, max_polls and duration_ns. G05 permits at most two commands, 64 status polls and 10 seconds; this is only the first entry scope, not a change to G05 or final requirements.

Replies use `{schema,id,operation_id,kind,status,result,error,unknown}`; trace result retains the original batch object. G05 successful result is original transaction facts with each exact started/returned file in lowercase hex. For the 1 MiB response budget, the fixed journal schema uses bounded request IDs, uint32 values, PID and monotonic scalars, bounding each original started/returned JSON at 512 bytes. Before any G05 mapping or CSR effect, the entry reserves `40960 + (50 + 100*commands + 2*max_polls + 3)*2176` bytes and requires the policy I/O quota to cover the same count. This calculation is a source-level bound requiring independent review; not an observed board result.

Any rejected or failed request terminates the session; unknown effects are never replayed and never cause an automatic STOP. In a G05 exception, original files remain on the board operation directory and no successful facts are fabricated; the bounded error reply is not a complete returned I/O receipt. The board-monotonic deadline is not a host QPC or physical completion claim.
