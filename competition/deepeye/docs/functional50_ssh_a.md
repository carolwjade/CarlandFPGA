# A-only persistent SSH transport (candidate)

Root must select the actual same-build BIT/HWH, remote script and plan, verify remote bytes and environment, resolve prior unknown operations, control the original SSH process and Job, and explicitly authorize the operation. Nothing here proves source, board readiness or acceptance. No real SSH/board call has been made in the new controls.

Construct immutable `SessionSpec(route, remote_python, remote_script, remote_plan, local_script, local_script_sha256, evidence_parent, operation_id)`. `route` is the existing 18-entry strict A route (without a remote command), with known fixed ssh.exe and host-key file hashes; the existing identity path is checked but its contents never read. `remote_python` is the fixed PYNQ venv Python. The script's local SHA is checked; **remote script and plan bytes are not read back or authenticated** and must be independently verified by Root before this operation. `open_session(spec, original_qpc_clock, sudo_input=one_time_bytes, timeout_ns=...)` uses one noninteractive SSH process, fixed `/usr/bin/sudo` and `/usr/bin/env BOARD=Pynq-Z2 XILINX_XRT=/usr`, and shell-quotes only strict absolute paths. Authentication bytes are sent once and never written to evidence. Do not use a different secret or connection without explicit Root selection. Previous sudo -n failure means a working root authentication path is still needed.

Successful open retains the original `Popen`, raw ready line and timing. `request(id, kind, offset, value, timeout_ns=...)` enforces the existing board port offset/command quotas and unique IDs, journals raw intent before the actual write, waits once for one bounded JSON response, journals its raw bytes and QPC upper observation, and validates exact response shape/ID. Lower and upper are host observations, not exact remote swap or MMIO intervals. There is no hard deadline inside the remote MMIO operation. A malformed, lost, timed-out or unrecordable response makes this session unknown and refuses subsequent calls. There is no retry or automatic cleanup.

All stdin sends use exactly one write and require the exact returned byte count; a short or unknown write is permanently unknown and is never repeated. `close_input()` closes local SSH stdin only and never claims the remote command stopped. For the original owner, `cleanup_local(kill=True|False, timeout_seconds=1..10)` is available even when the session is unknown or the SSH process already exited: it permanently retires the session, optionally attempts one local kill, waits for that same process, and only closes the streams and original Windows handle after all local I/O threads have stopped. It journals each actual observation; unconfirmed wait or outstanding threads leave the resources retained. Local process cleanup never proves the remote command stopped. Root retains the exact `original_process` and its outer Job ownership for termination/wait/handle closing; unknown outcome is not cleared by local process termination. If startup fails after `Popen`, `StartupUnknown.session` retains that same process, including any still-blocked original I/O thread. The started record alone does not prove a remote action or no action. `stderr_snapshot()` returns currently retained bounded raw stderr and overflow indication. Remote stdout beyond the single expected line can only be detected on a later read or process observation; Root must treat unsolicited/late output as protocol failure, not a receipt. This is not a hostile-process security boundary.

One port allows exactly one ARM and its bounded four-lane transaction; this transport cannot convert repeated captures into multiple ARM operations. Reducer, actual decoder, source and physical correlation remain separate future integration. Hardware/native timing and H01-H15 acceptance remain unproven.
